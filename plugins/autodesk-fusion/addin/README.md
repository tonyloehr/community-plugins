# Optional typed Fusion add-in

Use this route only after an administrator chooses it for a recorded native MCP gap or workstation policy. The plugin never switches into this route automatically. It runs the same reviewed Python handlers as the native adapter and exposes no Python evaluator, shell, arbitrary API reflection or machine-control endpoint.

Run the plugin build and install the **assembled** `dist/addin/CodexFusionInterop` folder through Fusion's Scripts and Add-Ins dialog. Do not install the source directory: the build copies `handlers/fusion_runtime.py` into the assembled package and writes `handler-manifest.json` containing its SHA-256. The loader verifies those exact bytes before execution. Fusion requires the folder, entry `.py` file, and `.manifest` file to have the same name. Start is manual by default. [Autodesk add-in installation and manifests](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/WritingDebugging_UM.htm)

The default endpoint is `http://127.0.0.1:27183/dispatch`. There is no port scan, remote bind, public tunnel, endpoint redirection or browser access. An optional `config.json` in the installed add-in folder may set `port`, `tokenFile`, `timeoutMs` (100–120000), and `maxQueue` (1–32). An explicit `tokenFile` must be an absolute canonical local path in a private directory. Defaults are:

- macOS: `~/.local/state/codex-fusion/addin/session.json` (expand the home directory when setting the plugin profile).
- Windows: `%LOCALAPPDATA%\CodexFusion\addin\session.json` (expand the variable when setting the plugin profile).

Select provider `addin` explicitly in the plugin's trusted desktop profile, with the exact endpoint and absolute token-file path. The host binds the expected handler hash from its installed canonical Python module. Stop and rebuild/reinstall both sides when that module changes; mismatched hashes fail before dispatch.

The add-in creates a new random secret and session identity each start. The secret stays in an owner-only file and is never returned to Codex tools or sent over HTTP. Requests and responses are HMAC authenticated with a nonce, timestamp and session binding. A signed status handshake precedes desktop requests. Browser Origin/Fetch-Metadata, unexpected Host, compressed/chunked bodies, duplicate authorization headers, replayed nonces, and oversized JSON are rejected. The plaintext loopback connection still depends on workstation trust; HMAC is not encryption or an OS sandbox. Another program running as the same user can read the pairing file or call Fusion directly. A malicious local port takeover can observe subsequent plaintext request data; these local trust limits must fit the deployment's policy.

On POSIX, the private directory and file require current-user ownership and no group/other permissions (normally 0700/0600). On Windows, fixed PowerShell ACL commands restrict a newly created directory to the current user and SYSTEM, then inspect both directory/file ACLs. Existing shared directories are refused rather than silently repermissioned. No execution-policy bypass is used. Windows ACL behavior and Fusion loading need validation on a supported Windows workstation before qualification; offline tests do not establish that result.

Network threads handle only plain data and invoke the documented `fireCustomEvent` signal. A retained `CustomEventHandler` dispatches the reviewed operation on Fusion's main thread. The operation handler independently checks idle-command, document identity and expected-state preconditions. No active command is terminated, no permanent `doEvents` loop runs, and no save/discard happens on shutdown. [Autodesk threading guidance](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/Threading_UM.htm)

Queued requests expire without execution. Once a handler starts, a timeout/disconnect is an unknown outcome, not proof of cancellation or rollback. The session retains request hashes to prevent repeated mutation execution; changed payloads under an old request ID are rejected. Completed result bytes have a bounded cache; evicted results keep a non-executing tombstone. The bounded mutation ledger stops admitting new requests when full. Stop/restart only after pending or unknown operations are reconciled; the ledger is not durable across an add-in restart. The outer control service remains responsible for durable plans and idempotency.

Stopping the add-in closes its listener, rejects queued work, unregisters its event, clears handler references, and removes only its own session file. This does not stop Autodesk's separate native MCP listener or secure other add-ins. A deployment that requires native MCP to be disabled must verify and enforce that separately.

Offline protocol and Python-threading doubles verify this implementation's boundaries. They do **not** prove native Fusion threading, geometry, entitlement, Windows ACL correctness, build compatibility or manufacturing safety. Qualify the selected provider and operation set against a licensed installation before enabling managed writes.
