# Autodesk Fusion implementation and validation status

Date: August 31, 2026. Package: `autodesk-fusion` 0.1.0. Branch: `codex/autodesk-fusion-interop`.

The user authorized implementation, testing and a pull request after the [research plan](autodesk-fusion-360-plugin-implementation-plan.md). The repository now contains an installable interoperability layer. **It is an implementation preview, not a qualified enterprise release.** The original acceptance contract remains in force; missing licensed tests, undeveloped variants and enterprise release work are not counted as complete.

## CAD feature expansion

The [CAD feature guide](../docs/cad-features.md) specifies the six added operation contracts and their required live geometry oracles. This work also corrects a real API mapping defect: construction planes and axes expose `.component`, not `.parentComponent`. Their finite origin/normal/direction observations now participate in entity and document freshness, including origin and custom construction geometry. Reading state does not refresh a stale selection. Existing sketch/revolve inputs benefit from the corrected ownership mapping.

The expansion preserves explicit cut/intersect participants, single-body joins, native component scope, parametric history, current state and unknown/partial outcome reporting. It adds bounded computed-profile checks and explicit separate-body mirror, split-extension and draft behavior. A planar split cutter may belong to a target body; it is a distinct face selection, not the same body object. No test-driven blanket prohibition was added.

Corpus revision 3 retains schema/scorer version 2 and all fixture prompts/observations. It archives exact v2 bytes, replaces the outdated all-loft-unsupported task under a new identity and adds twelve manual CAD cases. The current plan has 132 cases, 264 prompts and 792 run slots: 144 fixture and 648 requiring external environments. None of the new cases has a live execution or inherited passing grade.

Local verification of this expansion is tracked separately from the earlier candidate below. No older licensed, model, benchmark or compiled-contract result is relabeled as execution of the new handlers. Managed qualification must bind the changed handler and compiled implementation; the synthetic bracket does not simulate the six new operations.

## Workflow hardening after the CAD checkpoint

The local acceptance audit identified and implemented four workflow gaps beyond individual CAD operations. These additions do not change the 60-operation desktop denominator, the revision 3 corpus or any historical execution grade. The CAD test and model evidence above remains bound to its earlier executable contract. This workflow checkpoint has its own integrated verification below; neither focused nor full synthetic results are presented as enterprise-release qualification.

| W10 configure-to-order | [Whole-batch validation and recovery](../docs/batches.md), immutable unique variant/child mappings, bounded sequential admission waves, current grant/source/budget checks and durable output-conflict/validation-intent fences | No replay, automatic expiry refresh or direct Fusion/ERP publication. | W14 and exchange evidence | [Version 2 artifact provenance](../docs/artifact-fidelity.md) binds the recomputed producing plan, source observations, resolved options and actual successful response; PNG dimensions/CRC/container and finite STL facet grammar have bounded validators | No pixel decoding, full neutral/native model parse, round-trip kernel fidelity, collision proof or manufacture approval. Old receipts are preserved without regrading |
| R5 retention preparation | [Read-only inventory and copy-review planning](../docs/retention.md) under trusted owner periods and current expiring holds, with scope filtering and dependency protection for plans/jobs/artifacts/replay/accounting/drafts/conflicts | No copy/move/delete executor or remote/support-bundle cleanup. Actual periods, legal obligations and any collector or destructive action remain separately administered work |

Independent review found concrete defects and retained their original reproductions before repairs. Batch collisions now remain blocking after restart; interrupted output validation cannot disappear into a successful retry. Cancellation persists a fresh terminal observation without another DELETE or releasing reserved cost. A populated 100-variant batch now returns bounded summaries with exact receipt hashes/counts and per-job drill-down references instead of embedding every full validation receipt.

Engineering drafts preserve the handler's known fingerprint coverage gaps at initial, check, final and later inspection observations. Current criteria cannot rely on an old-source or missing-producer artifact. Strict stored schemas reject contradictory flags, oversized/duplicate selections, changed comparisons and missing unresolved gates even when a local record has been rehashed. This is content consistency, not authentication against the host owner. Sensitive assertion paths are rejected before reads; comparisons altered by redaction remain unresolved and store only sanitized scalars.

MCP input schemas now use Zod's input representation, allowing omitted defaulted fields to reach the server's actual defaults. The cloud atomic-concurrency default remains true. Shared-reference redaction protections remain in force; signed URLs, encoded redirects, URL userinfo and common credential fields are filtered without turning redacted placeholders into evidence of equality. Artifact completion recomputes the whole stored producer binding rather than merely comparing two hash fields.

The retention methods never initialize an absent ledger, write an audit or review record, invoke a provider or read credential subtrees. Ordinary MCP/CLI startup calls `engine.init()` first and can create the state root; launching the runtime is not an absence-preserving inspection. Retention takes its analysis clock after the snapshot so holds expiring during inspection cannot remain current. Incomplete directory observations expose lower bounds and null exact counts. These controls preserve existing profile ID/read-scope contracts and do not add retention startup requirements to desktop-only engines.

## Corrections to contradictory or nonfunctional components

- Updated research-only authorization/status language without calling enterprise milestones complete. Used released MCP SDK 2.0.0 and negotiated compatibility rather than an obsolete SDK pin inferred from historical protocol links.
- Separated configured, currently provider-reported and independently verified states. Native discovery is not API coverage, listener identity, entitlement or licensed execution proof.
- Made desktop read scope explicit: omitted `policy.readDocuments` means all current-user open documents; `policy.documents` limits writes only. Restricted reads filter status/listing too. Created/imported scope requires a successful bound producer receipt.
- Bound plans to compiled implementation, handler, profile, source state, input assets and expiry. Unknown or interrupted intent never permits replay. Fixed shared default asset registries so approved assets cannot leak between parsed profiles.
- Added structured managed desktop qualification for provider, Fusion build, broker platform/architecture/OS release, handler/contract, reviewer/evidence and expiry. Operation-ID qualification covers all admitted argument variants; no unimplemented argument-filter guarantee is claimed.
- Aligned facade/handler expression and identity limits, CAM integers and strategies, sketch cardinalities, and state/pagination preconditions, including BOM aliases.
- Included physical material definitions in state and required a current hash for assignment. Appearance/texture content remains excluded from engineering freshness and needs visual review.
- Kept asynchronous artifacts pending until exact provider completion. Inspection cannot finalize growing output. Public job status uses bound durable IDs rather than unchecked session future IDs.
- Required complete tool/holder/library, machine and post identity, current source-bound operator evidence, explicit NC controls and quarantine. Posting does not transfer, prove collisions or release to a machine.
- Serialized credential refresh, retained uncertain job/cancellation and cost reservations, and made output/billing completion consume trusted receipts instead of model-supplied success or charges.
- Withheld upstream native binaries whose exact Rust dependency resolution could not be reconstructed. Included the pinned upstream source, preserved community patch, new exact Cargo lock, Rust toolchain/build receipts and collected Cargo/C/Rust runtime notices. Fixed upstream read/delete error suppression and made partial credential cleanup visible and retryable. Native receipts and notices are checked against structured source/lock bindings and actual shipped bytes.
- Separated public PKCE from enterprise service authorization. The disabled reference recipe requires current service declarations and a licensed canary; it is not a working enabled recipe registry.
- Shipped declarations and installed research/status documents so installed users do not depend on erased interfaces or absent repository files.
- Enforced Windows private-state ACLs and ancestor replacement checks, with atomic protected-directory creation and no repair of existing shared ACLs. Added real-Windows-only cases rather than platform spoofing. Fixed the maximum-record newline boundary before replacing any existing record, and preserved hashed upstream notice bytes across Git checkouts.
- Fixed repeat-run qualification cleanup after persisted fixture results changed array order.
